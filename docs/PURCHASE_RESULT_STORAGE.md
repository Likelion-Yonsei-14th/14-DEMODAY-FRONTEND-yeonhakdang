# 구매 결과 보존

주문 생성 → 구매 당시 입력·선택·결과 고정 저장 → 결제창 준비 → 결제 완료 검증 → 저장된 주문 결과 열람 순서입니다. 저장 실패 시 결제를 진행하지 않습니다. 이름 등을 바꾼 새 주문은 새로운 요청 키를 사용합니다.

보관함에서는 최신 구매, 구매 내역에서는 해당 과거 주문의 결과를 엽니다. 유료 결과 화면은 서버가 소유권·결제·상품 권한을 확인하고 저장된 결과를 반환하기 전에는 결과를 표시하지 않습니다. 원본이 없으면 현재 입력으로 대체하지 않고 오류를 안내합니다.

부적은 최초 디자인과 다시 뽑기 3회분을 구매 시 저장하며, 서버가 현재 디자인과 남은 횟수를 관리합니다. 다른 기기에서도 이어집니다. 최초 열람 시각은 서버에 한 번 기록합니다.

결제 연결 전 모의 PaymentGateway로 검증한 범위:
- 저장이 끝나기 전에 결제창을 열지 않음, 저장 실패 시 중단
- 구매 당시 결과 복원과 과거 주문 선택 시 캐시 분리
- 결제 전·다른 계정·환불된 권한의 접근 차단
- 결과 불변성, 부적 횟수 제한과 중복 요청 차단, 탈퇴 후 개인 결과 삭제

백엔드 V1_2 마이그레이션을 포함한 배포가 먼저 필요하며 환경변수 추가는 없습니다. 실제 페이앱 연동·실결제·다른 기기에서의 실계정 검증은 별도로 진행해야 합니다. 현재 엔진이 프론트에서 생성한 결과 모델을 서버에 저장하며, 결제 금액과 상태는 기존 서버 검증 경로만 사용합니다.
