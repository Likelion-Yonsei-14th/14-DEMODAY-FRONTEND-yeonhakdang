# 연학당 프로토타입 계획

> 작성: 2026-10-14 · Figma `SyIjHZ302UZNLckGxBm3Zj` (데모데이 (사본))

## 목표

연학당 Figma 33개 화면을 **유저플로우대로 동작하는 단일 프로토타입**으로 만들고, 데모데이에서 데스크톱(폰 프레임)과 휴대폰(전체 화면) 양쪽으로 시연한다. 갤러리·화면 단건 뷰 등 기존 페이지는 모두 제거한다.

## 출발점 (현재 상태)

- `/proto`에 클릭 가능한 프로토타입이 이미 있다.
  - `components/proto/Prototype.tsx` — 이동 스택, 브라우저 뒤로가기, `#화면id` 해시, 데스크톱 폰 베젤 + 사이드바, 토스트, 메뉴 드로어. 상태는 `sessionStorage`(`yeonhak-proto`).
  - `lib/proto.tsx` — `ProtoState`(이름·생년월일·초대·로그인·약관·상품·대학·관계·구매·부적 횟수 등)와 `go / replace / back / backTo / reset / update / toast / openProduct / requireLogin` API.
  - `components/ui/Tap.tsx` — 모든 버튼의 단일 hotspot. 액션처럼 보이는데 핸들러가 빠진 버튼은 없다.
- Figma 화면 페이지(1:2)에는 **프로토타입 연결(reactions)이 0개**다. 경로의 근거는 "유저플로우" 페이지(46:117)에 화살표로 그려진 그림이다.
- 현재 코드의 경로는 유저플로우 페이지와 대부분 일치한다(아래 "경로 기준" 참고).
- git에는 CNA 초기 커밋만 있고 나머지 작업은 모두 커밋되지 않은 상태다.

## 작업 단계

### 1. 스냅샷 커밋
- 현재 작업 전체를 로컬에 커밋한다. 지울 `app/preview/`, `app/screens/`가 한 번도 커밋된 적이 없어서, 이 커밋이 유일한 복구 지점이다.
- 브랜치 이름을 `master`에서 `main`으로 바꾼다. **푸시하지 않는다.**

### 2. 프로토타입만 남기기
- `app/proto/page.tsx`의 metadata·viewport와 `ProtoLoader`를 `app/page.tsx`로 옮기고 `app/proto/`를 삭제한다.
- `app/screens/`, `app/preview/`를 삭제한다.
- `lib/screens.ts`에서 갤러리 전용 필드나 섹션 정보 중 프로토타입이 쓰지 않는 것을 정리하고, `5-artboard`를 등록 목록에서 뺀다. 공유 카드 컴포넌트는 PNG 저장에 쓰이므로 남긴다.
- `Prototype.tsx` 사이드바에서 갤러리 링크(`/`)를 제거한다.
- `app/not-found.tsx`가 9-3 `NotFound` 화면을 프로토타입 프레임 안에 보여주게 한다. 알 수 없는 `#id`도 9-3으로 보낸다.
- 정리 후 쓰이지 않게 된 코드를 지운다. 예: `Tap`의 비활성 `<div>` 모드, `FIGMA_STATE`/`STATIC_PROTO`처럼 정적 렌더링 전용인 부분. 실제로 참조가 없는지 확인한 뒤 지운다.

### 3. 경로 조정
- `KakaoMessagePreview`의 메시지 카드: `go("9-4")` 대신 `reset("1-2", { invited: true })`로 바꾼다.
- 9-4 `InAppBrowserSheet`의 버튼 동작은 유지한다. 9-4는 감지되거나 데모 패널로 열 때만 뜬다.

### 4. 데모 분기
- `ProtoState`(또는 별도의 `demo` 상태)에 다음 토글을 추가한다: `slowAnalysis`, `payFail`, `emptyRoster`.
- 각 분기 지점에 토글을 반영한다.
  - `AnalyzingLoading`: `slowAnalysis`이면 3-2로 `replace`한다.
  - `OrderPayment`의 `PaySheet`: `payFail`이면 자동 승인하지 않고 7-5로 보낸다.
  - `BottomNav`/결과 화면의 명단 진입: `emptyRoster`이면 4-2로 보낸다.
- 즉시 실행 버튼: "네트워크 오류(9-2) 띄우기", "인앱 안내(9-4) 띄우기".
- 진입 쿼리: 첫 로드에 `?invite=1`이 있으면 `reset("1-2", { invited: true })`를 실행하고, 쿼리는 URL에서 제거한다.
- 패널 UI
  - 데스크톱(≥ 900px): 기존 사이드바에 "데모" 섹션을 추가한다.
  - 모바일: `StatusBar`를 3초 안에 세 번 탭하면 패널(바텀시트 형태)이 열린다. 프로토타입이 켜져 있을 때만 동작한다.

### 5. 기능 보완
- **링크 복사**: `ShareScreen`의 링크 복사가 `navigator.clipboard.writeText(초대 URL)`를 실행한 뒤 토스트를 띄운다. 초대 URL은 `${origin}/?invite=1`. 클립보드를 쓸 수 없으면 토스트만 띄운다.
- **이미지 저장**: 현재 선택된 카드(학과 / 명단, 9:16 / 1:1)를 PNG로 저장한다.
  - DOM을 이미지로 바꾸는 라이브러리를 하나 추가한다(`html-to-image` 후보).
  - 인앱 브라우저에서는 기존대로 5-3 안내로 보낸다.
  - 웹폰트와 `public/assets` 이미지가 결과물에 정상적으로 들어가는지 확인한다.
- **로그아웃·탈퇴**: 두 버튼 모두 상태를 초기화하고 `reset("1-1")`. 위치는 `LockerMy`와 `MenuDrawer`. 탈퇴는 지금 토스트만 띄우므로 바꿔야 한다.
- **화면 없는 버튼**: 공지·FAQ, 약관 "보기", 구매 내역, 주문 정보 행 등에 "준비 중이에요" 토스트를 통일해서 붙인다. 지금 핸들러가 없는 7-4 `ListItem`도 포함한다.
- **입력값 표시**: `displayName` 외에 생년월일과 성별이 나오는 곳(보관함 프로필, 결과 상단 등)을 찾아 상태 값으로 바꾼다. 결과 내용은 고정이다.
- **상태 저장**: `Prototype.tsx`의 `sessionStorage`를 `localStorage`로 바꾼다. 읽고 쓰는 부분은 모두 try/catch로 감싼다. 저장 스키마에 버전 키를 둬서, 구조가 바뀌면 초기화되게 한다.
- **인앱 감지**: 첫 진입 때 user-agent에 `KAKAOTALK`, `Instagram`, `FBAN|FBAV`가 들어 있으면 9-4 시트를 연다. 세션에서 한 번만 연다.

### 6. README 재작성
실행(`npm run dev`), 배포 URL, 초대 링크(`/?invite=1`), 데모 패널 사용법(데스크톱 사이드바 / 모바일 상태바 세 번 탭), 상태 초기화 방법, 폴더 구조 요약을 담는다.

### 7. 검증
- `npm run build`가 통과하는지 확인한다. 동적 라우트를 지우면서 `instant` 같은 Next 16 설정이 남아 있지 않은지 확인한다.
- 모바일 폭(393px)과 데스크톱 폭에서 아래 시나리오를 직접 끝까지 눌러본다.
  1. 일반 진입: 1-1 → 2-1 → 3-1 → 3-4 → 명단 4-2(비초대) → 5-2 → 5-4 → 1-2
  2. 초대 진입: `/?invite=1` → 1-2 → 2-1 → 3-1 → 3-4(토스트) → 4-1 → 4-3 → 5-x
  3. 유료(단건 3종 각각과 패키지): 배너/탭 → 6-x → 7-1/7-2 → 7-3 → 7-4 → 8-x. 그 뒤 탭을 누르면 8-x로 바로 가는지
  4. 실패·예외: 분석 지연(3-2 → 재시도), 결제 실패(7-5 → 재결제 / 상품 상세), 9-2, 9-4, 잘못된 경로(9-3)
  5. 보관함: 드로어 → 9-1(로그인 2-4/2-5) → 각 결과 행 → 로그아웃 → 1-1 초기화
  6. 새로고침해도 상태가 유지되는지, 브라우저 뒤로가기가 정상인지
- 링크 복사(클립보드 내용)와 PNG 저장(파일 열어보기)을 실제로 확인한다.

### 8. 푸시와 배포
- `git remote add origin https://github.com/Likelion-Yonsei-14th/14-DEMODAY-FRONTEND-yeonhakdang.git` → `main` 푸시. 빈 저장소라 `main`이 기본 브랜치가 된다.
- 사용자가 Vercel 대시보드에서 저장소를 import한다. 조직 저장소라서 Vercel GitHub 앱 설치(조직 관리자 승인)가 필요할 수 있다.
- 프로덕션 URL을 휴대폰에서 열어 시나리오 1~2를 다시 확인한다. 공유는 프로덕션 URL로 한다.

## 열린 이슈 (Figma 내부 충돌, 기록만 함)

1. **결제와 추가 정보의 순서**: 유저플로우는 결제 → 7-4 → 7-1/7-2 순서이고, 화면 디자인(단계 표기 "1 / 2")과 코드는 7-1/7-2 → 7-3 순서다. 코드 순서를 따른다.
2. **로그인 시점**: 화면 페이지 02 섹션 설명은 "결과 보기 직전 카카오 로그인", 유저플로우 각주는 "보관함에서 다시 볼 때만 로그인"이다. 코드는 각주를 따른다.
3. **유료 결과 공유 카드**: 유저플로우에는 8-x → 결과 카드 공유가 있지만, 그 카드 화면 디자인이 없다.
4. **4-3에서 유료로 가는 입구**: 유저플로우에는 4-3 → 유료 화살표가 있지만, 4-3 화면에는 "확인" 버튼만 있다.
5. **떠도는 노드**: 화면 페이지 루트에 frame 31:1546(PG 안내 문구)이 있다. 7-3에 들어갈 요소로 보인다.
